# Architecture decision records

Create an ADR only when all three conditions are true:

1. The decision is costly to reverse.
2. A future contributor would find it surprising without context.
3. Real alternatives were considered and a trade-off was made.

Use the next four-digit sequence in `docs/adr/` and keep the record concise:

```md
# Short decision title

One to three sentences that state the context, decision, and reason.
```

Optional status, considered-options, and consequences sections belong only when they add information. Do not use ADRs as a daily log. Adding an event store always requires an ADR.
